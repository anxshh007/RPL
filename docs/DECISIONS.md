# RepoPilot AI — Team Decisions (overrides the member briefs where they conflict)

The five briefs in `docs/briefs/` were written separately and disagree in places. This file records the single answer for each conflict. **When a brief disagrees with this file or with `src/shared/contracts/`, this file and the contracts win.** Change a decision only through a PR approved by the Lead and all module owners.

| ID | Conflict found in the briefs | Decision |
|---|---|---|
| D-01 | Branch names differ: M1 lists `feature/impactlens`, `feature/testsheriff`, `feature/ui-diff`, but M3 says `feature/impact-analysis`, M4 `feature/test-verification`, M5 `feature/vscode-interface`. | Use **M1's list**: `feature/core-agent`, `feature/repository-context`, `feature/impactlens`, `feature/testsheriff`, `feature/ui-diff`. Short-lived sub-branches like `feature/impactlens-graph` are fine. |
| D-02 | Shared types location: M1 says `src/shared/contracts/`, M3/M4/M5 say `src/shared/types/`. | **`src/shared/contracts/`** only. `src/shared/types/` must not exist. |
| D-03 | Each brief proposes a different `ChangeRequest`, `ImpactReport`, `VerificationReport` and edge shape (e.g. `requestId` vs `id`; `risk` vs `level`; `reasons[]` vs `reason`; `from/to` vs `source/target`; `not-run` vs `not_run`). | One merged set in `src/shared/contracts/domain.ts`: M1's `ChangeRequest`; **M3's richer ImpactReport** (relationship path, confidence, summary, warnings — M5 needs these) plus `testCandidates` for M4; **M4's richer VerificationReport**, but with **nullable counts** so unknown is never `0`. Repository edges use `from/to`; UI graph edges use `source/target` (React Flow). Statuses are snake_case. |
| D-04 | Event names differ between M1 (`change.proposed`, `verification.completed`) and M5 (`plan.ready`, `diff.ready`, `verification.ready`, `agent.cancelled`). M5 also references a `ProposedDiff` type that doesn't exist. | One union in `events.ts`. Cancellation = `agent.status` with state `cancelled`. Added `agent.tool`, `agent.warning`, `verification.started`. `ProposedDiff` → `ChangePlan` / `ProposedFileChange`. |
| D-05 | No brief defines the hunk-decision, apply-result or undo contract, yet M1 and M5 both depend on them. | Added `HunkDecision`, `ApplyResult` (with `stale` status for hash mismatch), `UndoResult`, and the `EditService` interface. |
| D-06 | Overlap on the extension entry point: M1 owns "extension-host orchestration", M5 owns `src/extension/extension.ts`. | **M5** owns activation, commands, views and the webview bridge (`src/extension/`, `src/webview/`). **M1** owns the composition root `createRepoPilot()` (`src/agent/index.ts`), the orchestrator, MCP, and `src/edits/`. M5 calls only `AgentController`. |
| D-07 | M1 carries the most work (TrueForge + MCP + orchestration + edit service + all 11 tools). | **Tool handlers move to their owners**: M2 → search/read/symbol/context tools, M3 → `analyse_impact`/`get_impact_graph`, M4 → test tools, each in `<module>/tools.ts`. M1 only registers them in `src/mcp/`. Tool names are fixed in `src/mcp/tool-names.ts`. |
| D-08 | Every brief tells Antigravity to read `AGENTS.md`, but none defines it. | `AGENTS.md` at the repo root holds the shared rules and points to this file. |
| D-09 | "Do not guess package versions" and "record versions in the lockfile" vs a scaffold that has to compile now. | The scaffold uses only TypeScript + type packages. **Zod, Vitest, the MCP SDK, the TrueForge SDK, jsdiff, React/Vite/React Flow, Tree-sitter** are added by their owner with `npm install <pkg>`, so `package-lock.json` records real versions. The first such PR commits the lockfile, and CI switches to `npm ci`. Order: M1 adds `zod` + `vitest` first, everyone else after. |
| D-10 | Test folders: M2/M3/M4 use `tests/unit/<module>/`; M1/M5 don't say. | `tests/unit/<module>/` for everyone, `tests/integration/` shared by M1 + M5, `tests/fixtures/` for the Flask fixtures and the sample reports M3/M4 hand to M5. |
| D-11 | Validation: M1 requires Zod, the others say "if selected". | **Zod is selected.** Schemas live next to the contracts (`src/shared/contracts/schemas.ts`, added by M1). Until then, use `isWebviewToHost` and structural checks. |
| D-12 | M4 leaves the test-approval policy open; M1 requires "approval policy". | `repopilot.tests.requireApproval` (default **true**): the UI asks before every TestSheriff run. Only allowlisted pytest argument arrays are permitted. |
| D-13 | M2 suggests a 12k–20k token budget without a default. | `repopilot.context.tokenBudget` defaults to **16000** (estimated). M2 tunes it against the real TrueForge model. |
| D-14 | M1 requires `ImpactLens` before planning; M3 asks whether it runs before planning, before editing or both. | **Before planning** (on the retrieved context) and **again on `change.proposed`** with the proposed files, so the UI can compare predicted vs proposed. A failure in either call is a warning, never a blocker. |
| D-15 | TrueForge base URL default, event names and SDK methods are unknown. | `repopilot.trueforge.baseUrl` ships empty. M1 fills it in from the official docs and cites the source in the PR. Nobody writes TrueForge calls from memory. |
